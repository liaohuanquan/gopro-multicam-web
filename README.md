# GoPro HERO13 多机 Web 控制台

面向 Ego4D 四机采集的本地 Web 控制台。设备扫描 GoPro Labs 二维码后加入采集 Wi-Fi、应用统一录制参数，网页自动发现设备并执行真实状态查询和快门控制。

## 当前功能

- 扫码将 HERO13 加入采集 Wi-Fi
- 扫码统一配置分辨率、帧率、镜头、色深、色彩、防抖和码率
- 扫描局域网自动加入设备组，无需录入控制用户名或密码
- 多台设备永久保留，默认名称按 `GP01`、`GP02`、`GP03` 单调递增，并支持改名
- 相机 Wi-Fi 自动重连
- 单机蜂鸣和闪灯定位
- 设备上线后自动同步 UTC 时间码
- 显示剩余录制时长和 SD 卡剩余容量
- 录制期间通过 GoPro UDP 预览流实时监看，保持 16:9 完整画幅
- 显示服务器到每台相机的实时网络 RTT 延迟
- 添加设备时在当前浏览器记住 Wi-Fi 名称和密码
- 电量、SD 卡、温度、在线和录制状态
- 全部或指定相机开始/停止录制
- GoPro Labs 动态 UTC 时间码二维码入口
- 时间码扫码完成时间记录
- 每秒刷新设备状态
- 批量命令部分失败反馈
- 服务端生成未来 3 秒的 UTC 任务开始 / 结束切点
- 任务切点持久化到 Docker 数据卷，中途不修改相机时间码
- 导出任务事件 JSON，供四路连续视频按统一 UTC 自动切片
- 结束录制后通过局域网自动收集本次新增的 GoPro MP4

## Docker 启动（推荐）

```bash
./run.sh up
```

本机打开 `http://localhost:15173`；通过 SSH 部署时，使用服务器局域网 IP，例如 `http://192.168.1.205:15173`。

常用命令：

```bash
./run.sh dev     # 构建并在前台启动
./run.sh up      # 构建并在后台启动
./run.sh logs    # 查看日志
./run.sh ps      # 查看容器状态
./run.sh down    # 停止服务
./run.sh test    # 运行本地测试和前端构建
```

如需修改 Web 端口：

```bash
GOPRO_WEB_PORT=9000 ./run.sh up
```

默认扫描 `192.168.1.0/24`。采集 Wi-Fi 使用其他网段时：

```bash
GOPRO_SCAN_CIDRS=192.168.50.0/24 ./run.sh up
```

## 添加真实相机

1. 点击“扫码添加设备”，填写独立采集 Wi-Fi 及录制参数。
2. HERO13 扫描二维码，等待相机完成入网和参数配置。
3. 点击“扫描局域网并加入设备组”，网页会根据相机序列号自动登记。

该模式通过 HERO13 Labs 的 `OPNW=1` 开启无密码 HTTP 控制。只应使用隔离的室内采集 Wi-Fi，不要在公共、办公或不受信任的局域网中启用。

HERO13 开始录制后，卡片会自动请求 GoPro UDP 预览流，并通过 MJPEG 长连接持续推送监看画面；停止录制后会关闭该相机的预览进程。Docker 默认映射 UDP `8554-8561`，可同时接收最多 8 台相机的预览流。

## 连续录制任务切片

四台相机在开拍前完成一次 Labs UTC 时间码同步，随后保持连续录制。任务过程中不要再次写入相机时间码：

1. 在“UTC 任务切片”输入任务名称。
2. 点击“开始任务”，服务端记录未来 3 秒的 UTC 切点，页面显示倒计时。
3. 任务完成后点击“结束任务”，以相同方式记录结束切点。
4. 重复记录多条任务，最后导出任务事件 JSON。

点击“结束并收集”后，服务端等待相机完成写盘，再逐台读取媒体列表并只下载本次录制新增的 MP4。最多并行收集两台相机，进度显示在页面底部。结果直接保存在项目的 `data/` 目录：

```text
data/session_YYYYMMDD_HHMMSS_ffffff/
├── session.json
├── task_events.json
├── source/
│   ├── GP01/
│   ├── GP02/
│   ├── GP03/
│   └── GP04/
└── clips/
    ├── task_001/
    │   ├── GP01.mp4
    │   ├── GP02.mp4
    │   ├── GP03.mp4
    │   ├── GP04.mp4
    │   └── preview_grid.mp4
    └── task_002/
```

事件存储在 Docker 数据卷的 `/data/task_events.json`，格式包含 `task_id`、`start/end`、`utc_at` 和服务端创建时间。素材收集完成后，服务端自动读取 GoPro MP4 的嵌入时间码，按任务开始顺序生成 `task_001`、`task_002` 等目录。四台素材使用同一 UTC 区间精确重编码切片，避免关键帧造成的切点偏差。没有完整开始/结束事件的任务不会切片；缺失时间码或素材覆盖不完整时会将采集会话标记为失败并保留错误信息。

每个任务切片完成后会生成 `preview_grid.mp4`：2 台相机左右并排，3 台相机上二下一，4 台相机使用 2×2 四宫格。单台采集不生成宫格文件。该文件只用于快速检查多机位同步，独立的 GPxx 文件仍是正式结果。

任务按钮不会向相机发送时间设置命令；即使只有三台相机可被 Web 控制，只要第四台已经完成时间码同步并持续录制，也可以在后期使用相同 UTC 切片。
